# GNOME 잠금 해제 크래시 수정 패치

날짜: 2026-09-19 (KST)

## 설치 결과

Mutter의 키맵 교체 경쟁 상태를 고치는 GNOME 공식 패치를 Ubuntu 26.04 패키지에 백포트해 설치했다. 설치된 버전은 **50.1-0ubuntu2.4+keymapfix1**이다.

설치 후 파일 무결성·의존성·GNOME 동적 연결 검사가 정상이다. **현재 GNOME PID 95419는 설치 전 라이브러리를 메모리에서 사용하고 있으므로 재로그인이 필요하다.** 시스템을 재부팅할 필요는 없다. 현재 세션을 강제로 종료하거나 재시작하지 않았다. 실제 잠금·지문 해제 재시험은 재로그인 이후에 진행할 항목이다.

사용자는 재로그인을 나중에 하기로 선택했다. 따라서 설치는 완료됐지만 실행 중인 세션에 대한 활성화와 실제 잠금 해제 재시험은 사용자 일정에 따라 보류한다.

## 수정 내용과 패키지

- 공식 커밋: [709ef34381e51e83327b9c6d7270ed437d714768](https://github.com/GNOME/mutter/commit/709ef34381e51e83327b9c6d7270ed437d714768)
- 문제: 입력 스레드가 키맵을 교체할 때 메인 스레드가 같은 XKB 포인터를 읽어 NULL 접근 또는 해제된 메모리 접근이 발생할 수 있다.
- 수정: XKB 접근은 입력 스레드에서 수행하고, Caps Lock·Num Lock 처리에 필요한 값만 메인 스레드에 전달한다.
- 기준 소스: Ubuntu 공식 `mutter 50.1-0ubuntu2.4`. 업로더 서명과 소스 파일 SHA-256을 확인했다.
- Ubuntu의 기존 패치 30개와 패키징을 유지하고 공식 수정 1개를 추가했다. 수정 파일은 `src/backends/native/meta-keymap-native.c`이며 공식 패치 그대로 13줄 추가·7줄 삭제다.
- [적용한 패치 파일](./mutter-keymap-fix.patch)

| 패키지 | 설치 전 | 설치 후 |
|---|---|---|
| libmutter-18-0 | 50.1-0ubuntu2.2 | 50.1-0ubuntu2.4+keymapfix1 |
| mutter-common | 50.1-0ubuntu2.2 | 50.1-0ubuntu2.4+keymapfix1 |
| mutter-common-bin | 50.1-0ubuntu2.2 | 50.1-0ubuntu2.4+keymapfix1 |
| gir1.2-mutter-18 | 50.1-0ubuntu2.2 | 50.1-0ubuntu2.4+keymapfix1 |

빌드에는 GCC 15와 Ubuntu의 debhelper/Meson 설정을 사용했다. 빌드 도구·개발 라이브러리 175개를 추가로 설치했고, 이 준비 단계에서 기존 패키지 업그레이드·삭제는 없었다. 이후 위 Mutter 패키지 4개를 교체했다. 세손가락 드래그·지문 센서 드라이버·PAM·한글 입력기 설정은 이 작업에서 변경하지 않았다.

## 검증

| 검사 | 결과 |
|---|---|
| 컴파일·Debian 패키지 생성 | 성공 |
| Ubuntu 일반 자동 시험 | 177개 통과, 5개는 기존 예상 실패 항목 |
| 키맵 시험과 기존 드래그 라이브러리 병용 | 10회 반복 모두 통과 |
| 공개 동적 심볼 비교 | libmutter 996개, Clutter 1243개, Cogl 431개, MTK 82개: 원본 대비 추가·누락 없음 |
| 기존 GNOME 및 드래그 설정과 동적 연결 | 미해결 심볼·누락 라이브러리 없음 |
| 설치 파일 SHA-256 | 패키지에서 추출한 라이브러리 4개와 모두 일치 |
| dpkg 무결성·미완료 작업·APT 의존성 | 문제 없음 |
| 패키지 hold | 추가하지 않음 |

처음 자동 시험에서는 실행 앱에서 상속된 `GDK_BACKEND=x11` 때문에 Wayland 창이 필요한 19개 시험이 실패했다. 해당 환경값을 제거하자 19개 모두 통과했다. 통과한 158개와 재검증한 19개를 합산한 결과가 위 177개다. 예상 실패 5개는 Cogl의 알려진 그래픽 시험이며, 새로 발생한 실패가 아니다. 선택적 flaky/broken 시험 묶음은 실행하지 않았다.

검증 완료 후 중복 시험을 생략하고 패키징 단계만 이어서 실행했다. 패치 기능 시험을 생략한 채 설치한 것은 아니다. 실제 사용자의 잠금 화면에서 반복적으로 지문 해제하는 시험은 아직 완료되지 않았다.

## 재로그인 후 확인

작업을 저장한 뒤 Ubuntu 메뉴에서 로그아웃하고 다시 로그인한다. 화면 잠금 후 해제만으로는 실행 중인 GNOME이 새 라이브러리로 바뀌지 않는다.

이후 새 GNOME PID와 로드한 라이브러리를 확인하고, 한영 전환과 잠금·지문 해제를 시험한다. 패치 버전은 다음으로 확인할 수 있다.

```bash
dpkg-query -W libmutter-18-0 mutter-common mutter-common-bin gir1.2-mutter-18
```

## 원복

Ubuntu 공식 **50.1-0ubuntu2.4** 패키지 4개와 설치한 수정 패키지의 복사본·SHA-256을 다음 root 전용 디렉터리에 보관했다.

```text
/var/lib/local-mutter-keymap-fix/50.1-0ubuntu2.4+keymapfix1/
```

이번 수정만 제거하고 공식 Ubuntu 패키지로 돌아가려면:

```bash
pkexec /usr/bin/python3 /var/lib/local-mutter-keymap-fix/50.1-0ubuntu2.4+keymapfix1/restore.py
```

또는 [복구 스크립트](./restore-mutter-keymap-fix.py)를 실행한다. 복구는 최초 설치 버전 2.2가 아닌, 확보해 둔 최신 공식 2.4로 돌아간다. 이후 재로그인이 필요하다. 나중에 다른 Mutter 버전으로 업데이트된 경우 복구 스크립트는 무작정 다운그레이드하지 않고 중단한다.

## 향후 업데이트

일반 APT 패키지로 설치했다. 같은 공식 2.4는 로컬 패치 버전보다 낮으므로 보통의 업그레이드가 이번 패치를 즉시 덮어쓰지는 않는다. 다만 이후 공식 2.5 등 더 높은 버전은 이를 교체할 수 있으므로, 다음 Mutter 업데이트 때 [Ubuntu 버그 2152175](https://bugs.launchpad.net/bugs/2152175)의 수정 포함 여부를 확인해야 한다. 보안 업데이트를 막는 고정/hold는 적용하지 않았다.

소스, 빌드 결과, 검사 로그, 설치 명세는 작업 폴더의 `work/mutter-keymap-fix/`에 남겨 두었다. 최초 크래시 분석은 [별도 보고서](./gnome-lock-crash-analysis-2026-09-19.md)를 참고한다.

# 보관소 검증 결과

검증 날짜: 2026-09-19. 대상: Ubuntu 26.04 amd64, GNOME 50, EGIS `1c7a:05b1` 센서가 있는 기존 노트북.

## 이번 보관 작업에서 수행한 검사

| 검사 | 결과 |
|---|---|
| 소스·패치·원래 바이너리·라이선스 SHA-256 | 31개 파일 일치 |
| 지문/드래그 기존 설치 파일과 보관본 비교 | 3개 공유 라이브러리 해시 일치 |
| 기존 Mutter 설치 버전 | 패키지 4개 모두 `50.1-0ubuntu2.4+keymapfix1` |
| 세 구성 설치 및 지문/드래그 비활성화 모의 실행 | 성공; 실제 설정·서비스 변경 없음 |
| Mutter 공식 패키지 원복 모의 실행 | 4개 교체, 패키지 삭제 0개 |
| 다른 디렉터리로 전체 복사 후 실행 | 공백 포함 경로, 다른 작업 디렉터리에서 해시 검사·드래그 모의 실행 성공 |

| fingerprint 원본 추출 → 새 빌드 → 시험 → 산출물 생성 | 성공, 라이브러리 단위 시험 그룹 4개 통과 |
| drag 원본 추출 → 패치 → 새 빌드 → 시험 → 산출물 생성 | 성공, 일반 사용자 시험 그룹 9개 통과 |
| 새 fingerprint/drag 산출물의 ABI 연결 검사 | fprintd / GNOME 대상 `ldd -r`, 누락 라이브러리·미해결 심볼 없음 |
| 새 산출물의 설치 모의 실행 | 두 구성 모두 성공 |
| Mutter 원본 추출·Ubuntu 기존 패치 30개·로컬 패치 적용 | 성공, 적용 fuzz 0 |
| Mutter 빌드 의존성 검사 | 통과 |
| Python 문법 및 두 shell 진입점 구문 검사 | 통과 |

보호 장치 시험은 손상된 해시, 디렉터리 밖 파일 참조, 다른 OS/아키텍처, 알 수 없는 기존 설정, 드라이버 ABI 검사 실패, 서비스 reload 실패 때의 설정 복원, 반복 적용·비활성화, 최신 Mutter 다운그레이드 차단, libinput 기준 버전 변경, 이미 적용된 패치와 충돌 구분을 포함한다. 라이브러리를 교체해도 기존 파일을 열어 둔 프로세스가 읽던 내용은 유지되는지 확인했다. 실제 설치 동작은 임시 디렉터리와 모의 서비스에서 시험했다.

이번 drag 재빌드 환경에는 시스템 `python3-pytest`/`check`가 없었다. pytest와 의존 패키지를 공식 APT에서 받아 작업 폴더에만 추출하고 시험했다. 선택적 litest 자체 시험은 없어서 9개 그룹을 실행했다. 배포 레시피의 `deps drag`는 두 의존성의 설치 명령을 안내한다. fingerprint에서는 사용하지 않는 hwdb/AppStream 데이터 시험 문제를 확인해 라이브러리 단위 시험 범위를 명시했다. 자세한 내용은 [빌드 안내](building.md)에 있다.

새 빌드 파일은 컴파일 경로·옵션 차이로 기존 설치 파일과 해시가 달라질 수 있다. 보관소 루트 `artifacts/`는 실제 장치 검증을 마친 기존 바이너리를 유지한다. 새 파일을 현재 시스템에 설치하거나 실제 지문/드래그를 다시 시험하지 않았다.

## 이전 설치에서 이미 수행한 검사

- 지문: 실제 등록, 일치 인증, 미등록 손가락 거부, fprintd 재시작 후 인증 성공.
- 드래그: 일반 시험 10개 그룹, 빠른 세손가락 동작 관련 40개 시험 통과, 적용 대상이 아닌 조합 40개 확인.
- Mutter: 실제 컴파일·패키징·설치 완료. Ubuntu 일반 시험 177개 통과, 예상 실패 5개. 키맵 시험과 드래그 라이브러리 병용 10회 통과. 공개 동적 심볼과 설치 파일 무결성 검사 통과.

상세 근거와 당시 한계는 [원래 설치 보고서들](reports/README.md)에 있다. 이번 작업에서는 이미 검증한 Mutter 전체 컴파일·장시간 시험을 중복 실행하지 않고 소스 준비와 재설치/원복 경로를 확인했다. 새 Mutter 빌드 명령은 실행 시 원래 Debian 패키징의 시험을 수행한다.

## 남아 있는 실제 기기 검증

현재 GNOME은 아직 이전 Mutter 라이브러리를 메모리에 유지한다. 사용자가 작업을 저장한 뒤 재로그인해야 새 패치가 활성화된다. 그 뒤 한영 전환과 반복 잠금·지문 해제를 확인해야 한다. 다른 기기에서의 터치패드 동작·새 지문 등록·절전 후 인증은 해당 기기에서 별도 검증한다.

이번 작업에서 패키지 설치, 서비스 재시작, PAM 변경, 로그아웃·재부팅·절전은 수행하지 않았다.

## 후속 관리자 지문 인증 적용

위의 초기 보관 작업 이후, 2026-09-19 09:59 KST에 사용자의 추가 지시로 PAM 설정을 변경했다. sudo/sudo-i/polkit에 지문 우선 규칙과 약 10초 후 비밀번호 fallback을 적용했다. root 전용 백업은 `/var/lib/ubuntu-custom/admin-fingerprint/20260919T005935Z-648ju2eo/`다. 세 서비스 모두 실제 PAM 정책 로드·계정 검사를 통과했다.

새 설치 도구 시험 5개와 기존 시험 11개, 합계 16개가 통과했다. 비밀번호/계정/세션 정책 보존, 모의 실행 무변경, 기존의 다른 PAM 규칙 거부, 적용 실패 시 전체 원복, 반복 적용 및 후속 편집 보존을 확인했다.

실제 사용자 시험 결과:

- 첫 sudo 시도에서 약 10초 후 지문 대기 종료와 비밀번호 입력창 전환을 확인했다. 비밀번호를 입력하지 않고 취소했다.
- 곧바로 재시도할 때 fprintd가 `Unrecognized response from device`를 기록했다. 앞선 시간 초과 때 `g_task_return_error` 경고도 있었다. 기존 비공식 드라이버에서 관찰된 시간 초과/취소 후 상태 문제이며 PAM 정책 문법 오류는 아니었다.
- fprintd 서비스를 재시작한 뒤 `sudo -k -- /usr/bin/id -u`가 등록된 오른쪽 검지로 인증되어 `0`, 종료 코드 0을 반환했다.
- 별도의 `sudo -k -i /usr/bin/id -u`도 지문으로 인증되어 `0`, 종료 코드 0을 반환했다.
- 설치·설정 창과 같은 polkit 경로인 `pkexec /usr/bin/id -u`의 관리자 인증도 성공하여 `0`, 종료 코드 0을 반환했다.

서비스 재시작 이후 세 방식 모두 성공했지만, 이 시험이 드라이버의 시간 초과 후 응답 오류 자체를 수정한 것은 아니다. 동일 현상이 다시 나타나면 비밀번호 fallback을 사용하고 지문 서비스를 재시작할 수 있다. [사용·복구 안내](admin-fingerprint.md)에 기록했다. 실제 비밀번호를 입력해 성공하는 별도 시험은 이번에 수행하지 않았다. PAM 파일에서 기존 비밀번호 경로 보존과 비밀번호 프롬프트 도달을 확인했다.

## 후속 잠금화면 확장 설치와 활성화

2026-09-19에 `direct-unlock@testors.github.io` 버전 1을 작성해 사용자 확장 디렉터리에 설치하고 활성화 설정을 등록했다. 초기 세션에서는 새 확장을 인식하지 못해 재로그인 대기로 표시됐다. 이후 21:43 KST 확인에서 새 GNOME Shell 프로세스가 실행 중이며, 공식 `gnome-extensions info`와 D-Bus 조회 모두 확장 상태를 `ACTIVE`로 반환했다. 설치 파일 해시가 저장소 소스와 일치한다. 기존 세 확장의 활성화 설정과 비활성화 목록은 유지됐다.

- GJS 자동 시험 6개 그룹 통과: 화면 복귀 자동 표시, 중복 이벤트 통합, 잠금 해제·절전·입력 중 보호, 실패·취소 후 재시도 없음, 신호/idle callback 정리. Shell 객체는 모의 객체를 사용했다.
- Python 시험 총 22개 통과: 기존 16개와 새 설치 보호 장치 6개. 새 시험은 임시 디렉터리·모의 설정을 사용한다.
- 실제 GNOME 50.1에서 확장 모듈 로드 및 활성화 성공. 확인 시점의 최근 10분 사용자 로그에서 확장 관련 JavaScript 오류가 발견되지 않았다.
- 새 GNOME 프로세스는 설치된 `50.1-0ubuntu2.4+keymapfix1`의 Mutter 라이브러리를 로드하고 있으며, 기존 삭제된 라이브러리를 계속 매핑하던 상태는 해소됐다.

확장 활성화는 확인했지만, 사용자가 실제로 Enter 없이 지문 해제·비밀번호 해제·절전 복귀를 수행하는 시험은 아직 확인하지 않았다. 설치 과정에서 PAM 변경, 지문 서비스 재시작, 강제 잠금·로그아웃은 실행하지 않았다. [확장 사용·복구 안내](direct-unlock.md)를 참고한다.
